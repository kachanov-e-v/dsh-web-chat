# dsh-web-chat

[![version](https://img.shields.io/badge/version-0.10.1-blue)](CHANGELOG.md)
[![license](https://img.shields.io/badge/license-MIT-green)](LICENSE)

**DeepSeek (browser)** — модель для DeepSeek Harness, которая использует ваш
вход в [chat.deepseek.com](https://chat.deepseek.com/) через отдельный профиль
Chrome/Edge. Плагин не требует API-токена и не читает cookies.

> Это экспериментальный мост через DOM потребительского веб-чата. Он может
> сломаться при изменении вёрстки DeepSeek и может нарушать условия
> использования сервиса. Для стабильной работы в больших проектах используйте
> официальный API.

## Возможности

- Одна модель — `DeepSeek (browser)` (`deepseek-web`).
- Включение **по чату**: зелёный чип и выбор модели только в текущей сессии.
- Включение сохраняется между перезапусками DSH (только id сессий).
- Полноценный агентный цикл: `pwsh`, `read`, `write`, `edit`,
  `ask_user_question` и другие инструменты DSH.
- Разбор `<tool_call>` в code fence и нативного DSML DeepSeek.
- **`PROJECT_MEMORY.md`** — автоматическая память проекта, которую модель
  читает и обновляет.
- Компактификация истории, инкрементальные продолжения и лимит полного
  промпта 60 000 символов.
- Новый чат DeepSeek при достижении лимита веб-чата; ручная кнопка «Новый чат».
- Плавающая панель рядом с чипом, закрывается по клику вне окна.
- **Стриминг частичного ответа**: текст появляется в DSH по мере роста ответа
  в веб-чате, а не только после полного round-trip.
- **Уточняющие вопросы**: при неоднозначном запросе модель сначала спрашивает
  через `ask_user_question`, а не угадывает.

## Требования

- DeepSeek Harness Desktop с менеджером плагинов.
- Chrome или Edge.
- Аккаунт DeepSeek.
- Node.js только для запуска тестов.

## Установка

### Из GitHub

Последняя версия (ветка `main`) устанавливается **без тега**:

```text
github:kachanov-e-v/dsh-web-chat
```

Если нужна закреплённая версия — добавьте тег:

```text
github:kachanov-e-v/dsh-web-chat#v0.10.1
```

Репозиторий: https://github.com/kachanov-e-v/dsh-web-chat

`install_bundle` принимает эту спецификацию как installation spec. После
установки обновите страницу DSH (`F5`) и включите плагин в нужном чате.
Повторная установка без тега подтянет текущий `main` — это и есть «последняя
версия».

### Локальная разработка

```powershell
git clone https://github.com/kachanov-e-v/dsh-web-chat.git `
  "C:\Users\<you>\Desktop\dsh\Plugins\dsh-web-chat"
```

Затем установите локальный бандл через менеджер плагинов DSH
(`install_bundle` с путём к папке).

## Включение

1. Откройте панель плагина в строке composer и нажмите **«Включить»**.
2. Чип становится **зелёным** именно в этом чате; Host вызывает
   `sessionController.selectModel` и выбирает `DeepSeek (browser)` для сессии.
3. Если браузер не открыт — **«Открыть браузер»** и войдите в DeepSeek.
4. **«Проверить вход»** и **«Тест»** проверяют мост.
5. Начните новый запрос в этом чате.

Включение в одном чате не включает модель в других чатах. После перезапуска
DSH включение восстанавливается из `sessions.json`.

## Как это работает

1. DSH собирает системный промпт, схемы инструментов, память и историю.
2. В новом веб-чате отправляется полный промпт (до 60k).
3. В последующих запросах отправляется только продолжение с новыми
   сообщениями, чтобы не дублировать историю.
4. Ответ модели разбирается как `<tool_call>{...}</tool_call>` или DSML.
5. Пока DeepSeek печатает, плагин опрашивает DOM и отдаёт новые фрагменты в
   DSH; после стабилизации ответ разбирается окончательно.
6. Tool-call выполняют обычные инструменты DSH; результат возвращается модели.

Большие tool-результаты обрезаются до 10 000 символов; модель перечитывает
нужное через `read`/`grep`. Старые сообщения компактифицируются.

## Память проекта

При первом запросе в рабочей папке создаётся `PROJECT_MEMORY.md`:

- Goal, Stack, Structure, Decisions, Current state, Next steps, Commands;
- до 6 000 символов подгружается в каждый запрос;
- модель обновляет файл через `write`/`edit`;
- секреты, токены и пароли туда писать нельзя.

Память переживает длинные чаты, обрезку истории и новые чаты. Файл можно
править вручную.

## Лимиты и восстановление

- Полный промпт: 60 000 символов; мост: 220 000.
- При `EMPTY`/`NO_ANSWER` — новый чат не чаще раза в 10 минут.
- При `CONTEXT_LIMIT` («Length limit reached / Please start a new chat») —
  новый чат не чаще раза в минуту и повтор с полным промптом.
- Неразобранный ответ возвращает ошибку, а не создаёт новый чат.
- Ручная кнопка **«Новый чат»** доступна в панели.

## Приватность и безопасность

- Плагин **не хранит** API-токен и не читает cookies браузера.
- Вход выполняет пользователь в отдельном профиле Chrome/Edge.
- Промпт, история и `PROJECT_MEMORY.md` отправляются в DeepSeek — не пишите
  туда секреты.
- В `sessions.json` хранятся только id сессий, без промптов и ответов.
- Данные входа и `sessions.json` остаются в
  `$DSH_HOME/dsh-chat-model` для совместимости с прежним именем; переименование
  плагина не сбрасывает вход и включение.
- Маршруты плагина same-origin, тела запросов ограничены.
- Автоматизация потребительского веб-чата может нарушать условия DeepSeek.

## Диагностика

- **Модель не выбралась.** Панель покажет «model was not switched» или
  «Session model selection is unavailable»; выберите `DeepSeek (browser)` в
  селекторе модели вручную.
- **Length limit reached.** Плагин сам начнёт новый чат; если нет — нажмите
  «Новый чат». Если новый чат сразу упирается в лимит, уменьшите полный
  промпт/память.
- **Нужен вход.** «Проверить вход»; войдите в открытом окне.
- **Жёлтая плашка Chrome** про `--disable-blink-features` — косметическая.
- **`EMPTY`/неразобранный ответ.** Пришлите ответ из веб-чата; проверьте
  code fence/DSML и селекторы.

## Структура

- `index.js` — Host: мост, маршруты, LLM-адаптер.
- `client.js` — чип и плавающая панель.
- `lib/browser/*` — CDP-мост и селекторы DeepSeek.
- `lib/llm/*` — агентный промпт, парсеры, адаптер.
- `lib/memory.js` — `PROJECT_MEMORY.md`.
- `lib/persist.js` — включение по сессиям.
- `lib/routes.js` — same-origin API.
- `lib/state.js` — состояние плагина.
