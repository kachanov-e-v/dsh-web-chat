# ROADMAP

Текущая версия — **0.11.6**.

## 0.11.6 — сделано

- Голые закрывающие теги `</｜｜DSML｜｜>` (без `parameter`/`invoke`) больше не
  попадают в значения аргументов: пути вида `app.js</｜｜DSML｜｜>` и `workdir`
  с мусором ломали `read`/`grep`/`pwsh` (`spawn … ENOENT`).
- KaTeX-восстановление сохраняет переводы строк внутри формулы: многострочные
  PowerShell-скрипты приходят с `$`, дефисами и переносами.
- Полустримленный `<｜｜` больше не попадает в чат текстом.

## 0.11.5 — сделано

- Повреждённая DSML-обёртка больше не превращает ход в `EMPTY`: вызов
  разбирается, даже если `</…invoke>` потерян, а закрывающий `parameter`-тег
  слит со следующим открывающим.
- Аргументы, отрисованные как формула (`$…$` → KaTeX), читаются из TeX-исходника:
  команды PowerShell больше не приходят как `𝑐 = 𝐺𝑒𝑡−𝐶𝑜𝑛𝑡𝑒𝑛𝑡`.
- Неразборчивый tool-call для известного инструмента повторяется в новом чате;
  неизвестный инструмент даёт `UNKNOWN_TOOL` без лишнего запроса.
- «Голый» `questions: [...]` больше не стримится в чат как текст.
- Восстановление `ask_user_question` из «голого» `questions: [...]`, если
  DSML-обёртка повреждена: показывается карточка вопроса, а не JSON текстом.
- Протокол запрещает нативный DSML и требует fenced `<tool_call>` JSON.

## 0.11.3 — сделано

- Ответы, уточнения и вопросы `ask_user_question` — на русском.
- Код, команды, пути и имена инструментов не переводятся.

## 0.11.2 — сделано

- DSML-парсер понимает аргументы, записанные вложенными `invoke`-тегами
  (`invoke name="file_path"`), а не только `parameter`.
- Исправлены `read({})`, `glob({})`, `pwsh({})` и ошибки
  `missing required property`: аргументы больше не теряются.
- Тест на точный DSML от DeepSeek Web.

## 0.11.1 — сделано

- Детект деградации: бесконечный повтор `DSML`/`parameter name=` обрывается,
  web-чат сбрасывается, запрос повторяется с полным промптом.
- Промпт запрещает повторять tool-call/параметры и просит сначала сканировать
  большой проект, а затем читать только нужные диапазоны.
- Стабильность больших проектов: ядровые инструменты, память, компактификация,
  новые чаты при лимитах.

## 0.11.0 — сделано

- Кнопка **«Удалить все чаты»** в панели: двухшаговое подтверждение и удаление
  всех чатов из `chat.deepseek.com` через залогиненный браузер.
- Маршрут `POST /dsh-web-chat/browser/deepseek/delete-all`.
- Удаление только веб-чатов; DSH-сессия, вход и память проекта не затрагиваются.

## 0.10.4 — сделано

- Ядровые инструменты (`read`, `write`, `edit`, `glob`, `grep`, `pwsh`,
  `ask_user_question`) приоритизированы в бюджете 10 000 символов.
- Детект `Messages too frequent` и один повтор через 20 секунд.

## 0.10.3 — сделано

- Протокол инструментов называет `pwsh`, а не `bash`.
- Вызовы `bash` в JSON/DSML автоматически перенаправляются в `pwsh`, если в
  DSH доступен `pwsh`; вызов выполняется, а не остаётся текстом.

## 0.10.2 — сделано

- При первом запросе к `deepseek-web` сессия автоматически включается и
  сохраняется; `NOT_ENABLED` больше не блокирует свежий чат.
- Мягкий разбор `<tool_call>`: литеральные переводы строк и висячие запятые в
  JSON больше не превращают `ask_user_question` в текстовый блок.

## 0.10.1 — сделано

- При неоднозначном запросе модель обязана спросить пользователя через
  `ask_user_question`, а не угадывать.
- `ask_user_question` приоритизирован в списке инструментов, чтобы его схема
  не выпадала из бюджета 10 000 символов.

## 0.10.0 — сделано

- Плагин переименован в **dsh-web-chat**: package, routes, slot id, Cordis
  patch и GitHub repository.
- **Стриминг частичного ответа**: мост опрашивает DOM и отдаёт новые фрагменты
  в DSH до финального ответа.
- Tool-call маркеры (DSML/`<tool_call>`) останавливают текстовый стриминг,
  поэтому сырой tool-call не показывается как текст.
- Профиль браузера и `sessions.json` оставлены в старом каталоге, чтобы вход и
  включение пережили переименование.

## Ближайшие улучшения

1. **Самовосстановление селекторов DeepSeek.** Эвристический поиск composer и
   ответа при изменении вёрстки, понятная ошибка вместо `NO_INPUT`.
2. **Официальный DeepSeek API как fallback.** Нативные tool-calls, контекст и
   стриминг без DOM — для больших проектов и низкой задержки.
3. **Живые smoke-тесты.** Новый чат, `CONTEXT_LIMIT`, восстановление после
   `EMPTY`, выбор модели в конкретной сессии.
4. **Резервный выбор модели через клиентский model selector**, если
   `sessionController` недоступен в профиле.

## Известные ограничения

- Каждый шаг — браузерный round-trip; ответы медленнее API.
- Вёрстка DeepSeek может измениться.
- Контекст веб-чата ограничен; очень большие проекты требуют компактификации
  или API.
- Автоматизация потребительского веб-чата может нарушать условия DeepSeek.
